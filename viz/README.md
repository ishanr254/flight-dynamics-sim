# Viewer

A static web page that plays back flights computed by the simulator. It does no physics
of its own.

## Running it

Open `index.html` in a browser. Nothing else is needed: no server, no build step, no
network connection. The folder can also be put on any static web host as it is.

Keep the three parts together:

    index.html              the page
    vendor/three.min.js     Three.js r128 (MIT licence), the 3D library
    data/scenarios.js       the flights, generated by the simulator

## Regenerating the flights

    python3 -m cases.viewer_scenarios

writes `data/scenarios.js`. The data is a script, not a JSON file, because browsers do not
let a page opened from disk read JSON with a network request.

## Controls

- **Scenario**: which flight to play.
- **Play / Pause, Restart, Speed, Time**: playback; the time slider scrubs.
- **Camera**: Chase (behind the aircraft), Tower (a pilot standing by the runway), Top
  (the whole course from above, upwind to the left as in the rules figure), Orbit.

The readouts show speed, altitude, bank angle, load factor, control deflections and
thrust. A red label appears whenever the aircraft is outside the range in which the
simulator's aerodynamic model is valid. The aircraft is drawn larger than life (the
factor is shown on screen) so it can be seen against a course several hundred metres long.

## Scenario format

`data/scenarios.js` sets `window.FD_SCENARIOS` to a list. Each entry has:

| Field | Meaning |
|---|---|
| `id`, `title`, `group`, `description` | identification; `group` sorts the picker |
| `rate`, `duration` | samples per second, and length in seconds |
| `span` | wingspan in metres, used to size the aircraft model |
| `summary` | lines of text shown beside the animation |
| `events` | `[time, label]` pairs, shown under the title as they pass |
| `ground` | optional course markings: `half_length`, `downwind_east`, `altitude` (m) |
| `columns` | equally long arrays, one value per sample |

Columns: `north`, `east`, `altitude` (m); `q0`-`q3` (attitude quaternion, body axes to
north-east-down); `V` (m/s); `phi`, `theta`, `psi`, `alpha`, `beta` (rad; `psi` is
unwrapped); `load_factor`; `thrust` (N); `delta_m`, `delta_l`, `delta_n` (rad);
`valid` (1 inside the model's valid range, 0 outside).

## Axes

The simulator works in north-east-down. The page maps that to the scene as x = east,
y = up, z = south, which keeps the scene right-handed so a right turn looks like one.

## Origin

Ported from the Cornell DBF "Flight Dynamics Modes" page (the `flight-dynamics-visual`
repository). The scene, aircraft model, cameras and attitude indicator were kept. The
hardcoded mode formulas were replaced by playback of exported flights, the mode tabs by a
scenario picker, the mirrored axes were corrected, and the 3D library is now a local copy.
